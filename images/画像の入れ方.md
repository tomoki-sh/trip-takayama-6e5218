# images フォルダについて

各スポット・店の写真をここに入れます。**新しい旅行では、このフォルダは空にして始めます**
（ヒーロー意匠の `furin.svg` などSVGだけは残し、テーマに合わせて差し替える）。

## 手作業では集めない。tools/ で取る

```bash
python3 tools/places.py site tools/targets.json      # ① 座標・点数・営業情報・写真名
python3 tools/photos.py site tools/places.json 4     # ② 写真を各地点4枚DL
python3 tools/credits.py site tools/credits.json     # ③ 投稿者クレジットをフッターへ
```

②で `images/` に保存され、`images_manifest.json` に `DATA` の `images:[]` へ貼る形の配列が出ます。
**1枚ずつ探して保存する必要はありません。**

## 命名規約

- ファイル名は `tools/targets.json` の **`key` がそのまま接頭辞**になります。
  複数枚は `_2` `_3` `_4`（例: `ofusa.jpg` / `ofusa_2.jpg` / `ofusa_3.jpg` / `ofusa_4.jpg`）
- **拡張子を決め打ちしない。** photos.py がマジックバイトで判定し、PNG や WebP が返ることが実際にあります
  （奈良版でも `koryori_nara_2.png` が1件）。`images:[]` には**保存された実際の拡張子**を書くこと。
- `app.js` 側では `images: ["images/ofusa.jpg", "images/ofusa_2.jpg", ...]` のように参照します。

## 枚数

- **目標は1地点4枚**（メイン1＋サムネ3）。カードは `imgs.slice(1, 4)` で表示するのでちょうど使い切ります。
- **4枚に届かない地点は取れた分だけ**にします。駅など被写体の乏しい地点は2枚のこともあります。
  **無関係な画像で埋めない。**
- 画像が1枚も無い地点は絵文字プレースホルダーで表示されます（`renderImageBlock()` のフォールバック）。壊れません。

## 出典・クレジット

- 写真は **Google Place Photos**（点数と同じAPIキー）から取得します。投稿者に権利があります。
- **`index.html` フッターの `<details class="photo-credits">` に投稿者名を必ず載せること。**
  `tools/credits.py` が既存リストとマージして人数表記まで直します（あとから店を足したときもこれでOK）。
- 観光スポットで**ライセンスが明記された素材**（Wikimedia Commons 等）を使う場合も、同じフッターに出典を残します。
- 私的共有（Public＋noindex・URL推測困難方式）の範囲で利用し、可能なら自前撮影に差し替えます。

## 差し替え後の確認

`app.js` の参照と実ファイルがずれていないかを最後に必ず突き合わせます（奈良版は98参照・欠落0）。

```bash
python3 - <<'PY'
import re, pathlib
s = pathlib.Path("site/app.js").read_text(encoding="utf-8")
refs = set(re.findall(r'"(images/[^"]+)"', s))
files = {f"images/{p.name}" for p in pathlib.Path("site/images").iterdir() if p.name != ".DS_Store"}
print("欠落:", sorted(refs - files) or "なし")
print("未使用:", sorted(files - refs) or "なし")
PY
```
